# Функциональные тесты Async API

В этом каталоге находится инфраструктура для изолированного запуска функциональных тестов сервиса `async_api`.

Тестовое окружение поднимается через отдельный `docker-compose.yml` и не зависит от уже запущенного основного окружения проекта.

## Что проверяют тесты

Функциональные тесты отправляют реальные HTTP-запросы в запущенный FastAPI-сервис и проверяют его работу вместе с Elasticsearch и Redis.

### Фильмы

* получение фильма по UUID;
* получение списка фильмов;
* пагинация списка;
* сортировка по рейтингу по возрастанию и убыванию;
* сортировка по умолчанию;
* фильтрация фильмов по UUID жанра;
* полнотекстовый поиск по названию;
* полнотекстовый поиск по описанию;
* поиск по имени актёра, сценариста или режиссёра;
* получение похожих фильмов;
* отсутствие похожих фильмов;
* получение результатов из Redis;
* ответы для существующих и отсутствующих объектов;
* валидация UUID и query-параметров.

### Жанры

* получение жанра по UUID;
* получение списка жанров;
* поиск по названию;
* сортировка по названию;
* пагинация;
* пустой результат поиска;
* получение результата из Redis;
* ответы `404` для отсутствующих жанров;
* ответы `422` для некорректных параметров.

### Персоны

* получение персоны по UUID;
* поиск персон по имени;
* сортировка по полному имени;
* пагинация;
* пустой результат поиска;
* получение фильмов, связанных с персоной;
* поиск фильмов, в которых персона указана актёром, сценаристом или режиссёром;
* получение результатов из Redis;
* ответы `404` для отсутствующих персон;
* ответы `422` для некорректных UUID и query-параметров.

## Проверка Redis-кеша

Кеш проверяется отдельными тестами.

Общий сценарий выглядит так:

1. Тест отправляет первый запрос в API.
2. Сервис получает данные из Elasticsearch.
3. Сервис сохраняет результат в Redis.
4. Тест удаляет один из документов, который входил в первый ответ, из Elasticsearch.
5. Тест повторяет запрос с теми же параметрами.
6. Второй ответ должен полностью совпасть с первым.

Если удалённый документ по-прежнему присутствует во втором ответе, значит результат был получен из Redis, а не повторно сформирован из данных Elasticsearch.

Redis очищается между тестами, поэтому кеш одного теста не влияет на остальные тесты.

## Состав тестового окружения

Тестовый `docker-compose.yml` запускает четыре сервиса:

* `async_api` — тестируемый FastAPI-сервис;
* `elasticsearch` — отдельный Elasticsearch для функциональных тестов;
* `redis` — отдельный Redis для функциональных тестов;
* `tests` — контейнер с `pytest`, который запускает тесты.

Сервисы Elasticsearch, Redis и API имеют healthcheck-проверки.

Контейнер с тестами запускается только после того, как все необходимые сервисы перешли в состояние `healthy`.

## Структура каталога

```text
tests/functional/
├── coverage/                 # Файл и отчёты покрытия
├── src/
│   ├── films/                # Тесты эндпоинтов фильмов
│   ├── genres/               # Тесты эндпоинтов жанров
│   ├── persons/              # Тесты эндпоинтов персон
│   └── test_search.py        # Тесты полнотекстового поиска
├── testdata/
│   ├── documents.py          # Фикстуры тестовых документов
│   └── responses.py          # Преобразование документов в ожидаемые API-ответы
├── utils/
│   ├── helpers.py            # Общие вспомогательные функции
│   ├── wait_for_es.py        # Ожидание готовности Elasticsearch
│   └── wait_for_redis.py     # Ожидание готовности Redis
├── .env                      # Настройки тестового окружения

├── requirements.txt          # Зависимости функциональных тестов
└── settings.py               # Настройки тестов
```

## Тестовые данные

Тестовые документы создаются pytest-фикстурами.

### `genre_documents`

Создаёт набор жанров с детерминированными UUID, названиями и описаниями.

Часть жанров содержит слово `Space`, остальные используются как обычные жанры. Это позволяет проверять поиск и пустые результаты.

### `person_documents`

Создаёт набор персон с детерминированными UUID.

Часть персон содержит имя `Jason`, остальные — `Erik`. Каждая персона получает список фильмов и случайный набор ролей:

* `actor`;
* `writer`;
* `director`.

Для генерации используется фиксированный seed, поэтому данные одинаковы при каждом запуске.

### `movie_documents`

Создаёт фильмы на основе `person_documents` и `genre_documents`.

Для каждого фильма формируются:

* UUID;
* название;
* рейтинг;
* описание;
* один или два жанра;
* актёры;
* сценаристы;
* режиссёры.

Часть фильмов содержит специальные слова в названии или описании, что позволяет проверять полнотекстовый поиск.

## Работа с Elasticsearch

Для подготовки данных используется фикстура `es_write_data`.

Она:

1. удаляет тестовый индекс, если он уже существует;
2. создаёт индекс с нужной схемой;
3. записывает документы через bulk API;
4. выполняет refresh индекса.

За счёт пересоздания индекса тесты не зависят от данных, оставшихся после предыдущих запусков.

Для проверки кеша используется вспомогательная функция удаления отдельного документа с `refresh='wait_for'`.

## Вспомогательные функции

### `build_expected_page`

Формирует ожидаемый ответ для тестов списков.

Функция:

1. выбирает документы по переданным индексам;
2. сортирует их;
3. применяет пагинацию;
4. при необходимости преобразует документ Elasticsearch в формат API-ответа.

### Преобразование ответов

В `testdata/responses.py` находятся функции, которые преобразуют полные документы Elasticsearch в структуры, возвращаемые API.

Например:

* `genre_to_response`;
* `movie_to_short_response`.

Они используются только для формирования ожидаемых результатов тестов.

## Подготовка окружения

Перед запуском убедитесь, что в каталоге `tests/functional` существует файл `.env` с адресами тестовых сервисов.

Внутри Docker-сети используются имена сервисов из `docker-compose.yml`, например:

```env
ELASTIC_HOST=elasticsearch
ELASTIC_PORT=9200

REDIS_HOST=redis
REDIS_PORT=6379
```

Точные имена переменных должны соответствовать `settings.py` и конфигурации `async_api`.

## Запуск тестов

Команды выполняются из каталога:

```bash
cd tests/functional
```

Запуск с пересборкой образов:

```bash
docker compose up --build \
  --abort-on-container-exit \
  --exit-code-from tests
```

Параметры команды:

* `--build` — пересобирает образы перед запуском;
* `--abort-on-container-exit` — останавливает окружение после завершения контейнера тестов;
* `--exit-code-from tests` — возвращает код завершения контейнера `tests`.

Внутри тестового контейнера выполняется команда:

```bash
python -m tests.functional.utils.wait_for_es &&
python -m tests.functional.utils.wait_for_redis &&
pytest -v tests/functional/src
```

Скрипты ожидания дополнительно проверяют доступность Elasticsearch и Redis перед запуском pytest.

## Повторный запуск после изменения API

Код `async_api` копируется в Docker-образ при сборке. Поэтому после изменения эндпоинтов, моделей или OpenAPI-документации необходимо пересобрать тестовый сервис:

```bash
docker compose up --build --force-recreate
```

Для полной пересборки без Docker-кеша:

```bash
docker compose build --no-cache async_api tests
docker compose up \
  --abort-on-container-exit \
  --exit-code-from tests
```

## Запуск отдельного теста

Чтобы запустить конкретный файл:

```bash
docker compose run --rm tests \
  pytest -v tests/functional/src/films/test_films.py
```

Чтобы запустить конкретную тестовую функцию:

```bash
docker compose run --rm tests \
  pytest -v \
  tests/functional/src/films/test_films.py::test_get_film_by_id
```

Чтобы оставить вывод `print` в терминале:

```bash
docker compose run --rm tests \
  pytest -v -s tests/functional/src
```

## Покрытие кода

Сервис `async_api` запускается под `coverage`.

Файл покрытия сохраняется в общем volume:

```text
tests/functional/coverage/.coverage
```

После завершения тестов вывести отчёт можно командой:

```bash
docker compose run --rm async_api \
  coverage report -m
```

Создание HTML-отчёта:

```bash
docker compose run --rm async_api \
  coverage html -d /coverage/htmlcov
```

После этого отчёт будет доступен в каталоге:

```text
tests/functional/coverage/htmlcov/index.html
```

Покрытие собирается для реально запущенного приложения, поэтому в отчёт попадают строки, выполненные при обработке HTTP-запросов и при запуске или завершении FastAPI-сервиса.

## Очистка окружения

Остановить и удалить контейнеры:

```bash
docker compose down
```

Удалить также тестовые volumes:

```bash
docker compose down -v
```

Удалить контейнеры-сироты:

```bash
docker compose down --remove-orphans
```

## Изоляция тестов

Функциональные тесты используют отдельные контейнеры Elasticsearch и Redis.

Они не должны подключаться к хранилищам основного окружения проекта.

Дополнительно обеспечивается изоляция данных:

* индексы Elasticsearch пересоздаются перед тестами;
* Redis очищается между тестами;
* используются детерминированные тестовые документы;
* каждый запуск выполняется в отдельном Docker Compose-проекте.
